# 验证、定界与交接

## 运行前

核对当前解释器、相关模块实际导入路径和必要版本；涉及下游编译时核对实际 compiler、CANN 与目标设备。复现包只说明必要环境，不默认导出完整环境快照或校验历史绝对路径。普通验证不生成或反复比对文件哈希；仅在用户明确要求或具体完整性/二进制来源问题确有必要时使用。抽取本身不修改安装包或重新编包。

保持原始缓存和失败产物用于取证。若要排除旧编译缓存，为本次运行建立个人持久化目录下的新缓存，不删除整个共享缓存。记录缓存路径和命中情况；缓存命中不能证明本次编译成功。

## 三类验证

| 类型 | 验证目标 |
|---|---|
| 编译失败 | 独立脚本/固定 IR 经过相同编译入口与配置，产生相同的首条实质错误、pass/代码位置和退出状态；只有新的缺包错误不算复现 |
| Runtime 异常 | 新进程中完成初始化与编译等待；对目标调用前后做必要的 `torch.npu.synchronize()`，将前序异步失败与目标调用隔开。记录同步引入的行为变化和原异常；不因错误字符串都包含 RuntimeError 就视为相同问题 |
| 精度问题 | 同一输入、参考计算、初始化和既有容差下复现原错误，列明输出/梯度、NaN/Inf、误差与阈值；执行退出 0 但没有参考比较不算精度验收 |

精度比较保留原参考的来源、dtype、计算公式、比较函数及参数顺序；`assert_close(a, b)` 的相对容差依赖第二个参数，不能为了变量名习惯对调。超差元素统计与最终断言使用同一判据，包括 NaN 处理。参考只是捕获的 eager FP32 时明确标注，不称作 FP64 golden；其他算子示例中的 scale、split 合并、阈值或输出位置不直接套用。若参考本身有问题，单独说明、按授权处理，不能悄悄换标准。比较失败返回非零，不只打印 FAIL；编译/运行时问题则保留对应的真实异常。

解释器可用且与任务相关时，用同一 kernel、输入和比较标准执行；不可用时明确未验证，不制造空日志或改算法凑 PASS。若交付单因素开关对照，两个分支用相同输入和配置、新进程及必要的独立缓存，只改变目标选项；通过该版本真实支持的配置入口设置，并从本次生成的编译 metadata 或实际 compiler argv 确认生效，不能仅打印请求值作为证据。不修改外部安装包来注入开关。

验证过程中发生的设备上下文错误不能靠继续在同一污染进程中重跑来判断；新进程再检查环境，仅清理本任务资源，不重置共享设备或结束他人进程。既有输入/配置下不复现时保留该结果，检查并发、别名、数据、前驱依赖与后端，不随机反复试参数直到得到另一种错误。

Bash 经 `tee` 保存日志时紧接着读取 `PIPESTATUS[0]`，返回测试进程的退出码；PowerShell 在原生命令结束后立即保存 `$LASTEXITCODE`。同时记录超时、信号和设备错误，不能只 grep PASS。命令使用已核实的实际路径，不把 wiki 中的 root 或历史模型命令复制给用户。

## 定界边界

抽取成功是交付独立证据的进展，不自动完成根因定责。区分“异常暴露在编译器”和“输入合法且缺陷位于编译器”；即使固定后级 IR 重放失败，也可能是 TorchNPU/TA 输出非法语义。

最终已证实的责任按当前项目约定分别写 TorchNPU、TA、NPU IR 或其他具体组件；TA 与 NPU IR 不合并成一个模糊结论。调查中证据不足写“归属未证实”，继续能做的定位；不能为填写最终分类猜选。外部问题不修改外部源码、二进制或安装包，不在 TorchNPU 中屏蔽其错误。

## 内部验证证据

按实际需要保留以下证据供定位和复核；它们不是默认交给用户的附件，无需创建空文件凑清单：

- 相关原始日志、output code、目标 kernel/IR 的原件和来源；不例行附加哈希清单。
- 独立复现脚本、必要的固定数据或确定性生成方式；标明是否保留最小前驱初始化。
- 环境信息、目标架构、实际参数/配置、原测试 node ID 或完整模型命令和失败调用映射。
- 一条可执行复现命令（含 cwd、必要环境变量、选定卡号）、运行日志、真实退出码。
- 简短结果：目标错误是否复现、具体错误位置/误差、尚未确定的责任边界和复现缺口。

## 软件包交付检查

交付精简目录或压缩包，只含复现入口、实际必需的数据/IR/helper、最终运行日志及简短运行说明。不把内部组包脚本、试跑日志、缓存或无关附件纳入交付，不加入自定义 `CAPTURE`/`ORIGINAL_ENV` 字典、环境哈希校验或通用审计框架；内部原始证据继续保留，不为精简交付而丢弃。

结果日志保留实际命令、必要模式/环境信息、stdout/stderr及退出码；精度日志给出比较对象、参考来源、阈值、超差数、误差与NaN/Inf统计。允许把同一设备的两个必要对照合并到一份日志，但每段清楚标识命令、选项和退出码。保留非预期警告和退出清理异常，按时间及执行阶段区分它们与首个实质失败。失败值含NaN或多次运行间波动时如实报告，不能挑选好看的数值覆盖真实日志。

验证最终软件包时，在同一目标环境将包复制或解压到与原证据目录分开的工作目录，按交付命令运行，确认只依赖包内文件和已说明的安装环境。检查入口与必要文件是否齐全、运行是否复现原错误，不把逐文件哈希校验作为默认验收步骤。仅在检查到路径遮蔽时调整 PYTHONPATH，不改动基础环境。

文件名可按任务微调，但验证命令必须指向最终名称；同时核对 import、相对路径、kernel 符号与日志标识。比较顺序、参数恢复或启动逻辑有修正后，重新验证受影响的最终入口，不能把旧日志配给新逻辑。组包时检查实际文件集合、源码必要部分及数据恢复的一致性；不要把某次交付的文件数量、编号、dtype、阈值或PASS/FAIL组合写成通用验收断言。

最终回复给软件包链接、一条入口命令和简短复现状态，不让用户自行组装零散片段。若无法运行或尚未复现，准确说明缺口，不把“已打包”当作“已复现”。

结果状态准确区分：“仅静态抽取”“可运行但未复现原错误”“已复现同一编译/Runtime/精度问题”“未运行（具体原因）”。有限验证通过后不为了抽取任务扩大到全模型/全量用例。

wiki 的容器/问题表格如适用于当前环境，可准备环境名、镜像/包标识、负责人、保留用途、任务编号、证据路径和复现状态，由用户登记或在明确授权后写入。来源文本没有真正表格 URL 时不可编造链接。默认不上传 kernel、测试或数据，不创建工单或发送消息。
