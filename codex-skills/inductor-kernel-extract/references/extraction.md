# 手工抽取与输入恢复

本流程以用户 wiki 中的 `async_compile.triton(...)` 和 `.run(...)` 形式为例。生成代码跨 torch/TorchNPU/Triton 版本会变化，现场代码优先；wiki 的 cat kernel 仅用于理解结构，不作为所有问题的固定模板。

## 从日志映射到代码

先在用户指定目录内按 kernel 名、output code 路径或第一条错误搜索；优先 `rg -n`，远程无 rg 时用 grep/Python。日志提及多个命令时核对返回码与时间，找到失败那条，不执行全部历史命令。完整日志无生成文件路径时，先查当前任务产物；必要时在当前版本支持的日志/调试开关下最小复跑原用例，不猜固定 cache 路径。

检查 kernel 的 Python 绑定名、`async_compile.triton` 第一个名字参数、内嵌函数名、日志名称及调用位置。名字可以不一致，依据编译绑定和调用关系匹配。wiki 文字举过 `triton_poi_fused_cat_0`，完整代码却是 `triton_unk_fused_cat_0`，不能按前缀相似自动替换。

## 保留编译结构

先复制完整原 output code 和关联源文件，再从副本组装独立脚本：

1. 保留目标所需的 import 和全局初始化，包括当前版本实际使用的 `AsyncCompile`、TorchNPU 注册、device/stream/helper。先忠实迁移再删无关依赖。wiki 存在重复 import、CUDA/XPU guard、版本相关私有 API，不作为跨版本必备项；新环境缺少某 import 不足以证明原 kernel 有错。
2. 复制完整目标 `async_compile.triton(...)` 赋值：源码、装饰器、signature、constants、device 属性、triton_meta、inductor_meta、device_str 以及用到的 helper/常量。保留源码外相关全局定义；内嵌源码依赖不能仅通过外层 AST 自动推断。
3. 按原实现实例化编译器，并保留 `async_compile.wait(globals())` 或该版本等价的等待机制。必须在访问/运行异步编译对象之前等待完成；不能因为单 kernel 就随意移除同步。`del async_compile` 仅在原代码需要时保留。
4. 保留原调用的参数顺序、位置参数/关键字参数、运行 grid、constexpr、stream 和配置。若还有 autotune/multi-kernel 包装，记录实际失败候选，而不是只报告外层包装名。首次复现可保留原候选选择，进一步固定时保留失败候选的 tiling 和 launch 参数。

精简启动包装时，若当前安装版本证实原 template 装饰器支持直接 `.run()` 同步编译和启动，可将内嵌 kernel 作为普通模块保留，移除不再使用的外层 AsyncCompile。保留原装饰器、完整 helper、编译元数据和调用语义，记录这项包装变化，并用最终入口验证同一失败；不能仅根据历史示例假设 API 可用。仍采用异步编译时必须等待完成，任何启动方式都不能省掉必要的设备同步。解释器与设备入口按当前 runtime 支持选择，不为得到解释器 PASS 改写 kernel 数学。

## 恢复输入输出

逐个追踪 `.run(...)` 的参数到原 `call(args)`、分配和重解释语句。下列信息用于恢复实际调用，不要求在交付代码中再建立 `CAPTURE` 字典或通用元数据框架：

| 项目 | 要保留的信息 |
|---|---|
| Tensor | shape、stride、dtype、device、storage_offset、所需存储长度 |
| View / 别名 | 共享 base storage、reinterpret/view 关系、输入输出重叠与原地写入 |
| 标量/符号 | 实际标量值、符号维度的失败实例、constexpr 和取值约束 |
| 运行元数据 | grid、stream、逻辑/物理设备映射、当前选中的配置 |
| 前驱依赖 | 由其他 kernel 生成的索引、计数、mask、元数据和中间 Tensor |

- 普通随机浮点输入可在确认数值范围和数据无关性后用当前版本的 `rand_strided`，并保留 `from torch._dynamo.testing import rand_strided`。输出 buffer 仅在写前不需要读取时可用 `empty_strided`；累加/原地算子需要正确初始值。
- 索引、offset、长度、稀疏元数据及指针表必须遵守原始合法范围；随机填充可能制造新的越界，不能用这种错误声称复现原问题。
- 数据相关 runtime 或精度问题优先保存失败调用之前的真实输入。固定 seed 只保证生成过程可重复，不保证等于原失败输入；说明数据来源，必要时保留相关前驱初始化。
- 克隆 Tensor 或分别分配相同 shape 不一定保持 storage_offset、stride、别名或地址对齐。显式重建 base/view 关系，核对最小存储范围；不默认把所有输入转为 contiguous。
- 若独立运行必须包含一个前驱才能保持语义，明确交付为“目标 kernel 加最小初始化链”，继续缩小可独立部分，不能隐藏前驱后仍声称纯单 kernel。

wiki 示例中有 6 个 `(32,1,1)`、stride `(1,1,1)` 的浮点输入和 `(32,1,6)`、stride `(6,6,1)` 的输出，调用参数顺序是 `arg5_1` 到 `arg0_1`。这些数字只适用于示例；实际任务逐项取自失败 output code，不按变量编号重排。

## 组织精简复现软件包

- 以目录或压缩包交付。kernel 文件保留目标代码及直接可读的输入构造，比较/运行逻辑按需要单独放置；小型复现可合并。具体命名和组合按 [命名与精简交付](package-layout.md)。依赖已安装的 Torch/TorchNPU/Triton 栈，但不依赖包外原测试仓、调查目录或缓存源码。
- 固定输入优先使用能保持原失败的简单确定性构造；数据相关问题使用真实捕获值。单用例、体积可接受且方便转交时，可把输入和参考数据压缩编码到 kernel 末尾，正文只保留简短解码和显式构造。数据很大、需多人独立检查或多个用例共享时，使用包内数据文件及相对路径。不强制内嵌，也不禁止内嵌；均需核对恢复后的数值、dtype、stride、offset和别名。
- 不自行添加 `CAPTURE`、`ORIGINAL_ENV` 等自定义来源字典、通用参数恢复框架、环境指纹或运行前哈希断言。简短来源和必要版本写说明即可；原生成代码要求的编译元数据照常保留。
- 只包含必要前驱初始化，并注明范围；不能把整网装进包后称作单 kernel 抽取。
- 仅当固定 IR 是所需复现方式时，将 IR 文件和实际编译/调用入口放在包内。只交付用户要求或解释当前问题确需的运行模式与开关，不附加无关实验。
- 简短说明包含环境要求、一条入口命令、预期错误和验证状态。不添加自动安装、环境重建、pip 打包配置或与复现无关的功能。

## 裸 kernel 与 IR 的语义保留

只有裸 `@triton.jit` 函数时，保留该版本实际 JIT 启动方式、参数及配置，不强行补成 AsyncCompile 包装。只有 TTIR/后级 IR 时，保存原编译器入口、完整参数、目标芯片和相邻阶段产物；是否还经过 TA 转换需要现场验证。

不得“修正”抽出的 IR 使其能够编译后，仍将其当作原始失败证据。简化版本另存，记录每项变化及失败是否保持。
