# Wiki 来源与环境适用性

本参考整理自《Inductor日构建问题定位和单Kernel抽取》的日志与生成代码示例。原始 wiki 和附件不随技能分发；使用本技能不依赖原项目归档。示例只用于解释结构，实际路径、版本及资源条件以当前任务为准。

附件含图片占位和表格标题，没有图片本体、可用表格链接或 `outputcode_get_all_ut.rar` 工具文件。未知内容不能从标题或示例补造。

## 日构建日志可复用步骤

1. 从用户提供的日构建目录进入 `logs`，按具体模型找日志；搜索 docker/image/install/run 命令和首条失败。仅搜索命令文本，不执行日志作为脚本。
2. 提取镜像、包目录、实际失败命令及对应配置，和当前复现环境比较。保留导致差异的版本、参数和依赖证据。
3. 在已授权、已核实的个人运行环境复现目标失败。wiki 中 `install.sh` 安装整套日构建包的命令只用于解释当时流程，不是抽取前置步骤；不自动在基础环境重装，不把修复安装包和保留原始失败混在一起。

## 不直接照抄的操作

- wiki 的 `docker run --privileged`、host 网络、超大 shm、挂载 root SSH/驱动和 `docker exec` 来自特定旧环境，不直接照抄。若当前任务确需重建专用容器，先确认现有权限和具体授权，不靠改名获得隔离或权限。
- 历史主机、IP、卡号、镜像和数据目录仅为来源线索。当前路径按项目环境文档或现场查证，使用个人持久化任务目录，不把 `/tmp` 当归档。
- 资源按当前 CPU、内存及 cgroup 配额安排；无需为了抽取重建 wheel，也不能把 `nproc` 当实际配额。
- 按用户最新规则自主检查空闲 NPU 并选择卡号，不要求预约/占卡声明；不操作他人进程或占用全部设备。遇无空闲资源，继续静态抽取与依赖分析。

## Wiki 自动抽取工具（条件使用）

原文工具名为 `outputcode_get_all_ut.rar`，解包脚本名 `outputcode_get_all_ut.py`，使用形式是：

```bash
python3 /verified/path/outputcode_get_all_ut.py /verified/path/output_code.py /personal/new-output-directory
```

本技能不包含该工具本体，不能声称已安装、下载、审计或验证；不要按文件名猜测下载地址。本技能自带的 `inspect_output_code.py` 是独立静态辅助脚本，不是 wiki 工具的替代实现，也不自动生成完整 UT。

仅在任务环境实际已有可信工具时，先检查来源、帮助/源码、依赖、输入输出及副作用，再在独立个人输出目录使用。未审阅工具前不要假定 `--help` 没有副作用。若工具导出全部 kernel，进一步依据原失败绑定选目标，检查输入、等待、配置、stream 和版本；导出数量不是复现证据。缺工具时继续手工抽取流程，无须为此暂停整个任务。
