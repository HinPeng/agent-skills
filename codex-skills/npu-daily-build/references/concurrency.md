# 编译并发与失败续建

## 选择起始并发

默认源码编译目标为 64；用户明确给出的值优先，始终受当前任务可用资源限制。TorchNPU、TA 和 NPU IR 分别执行这一策略，不把 uv 的下载/安装并发当作 C++ 编译并发。

- CPU 上限取进程 affinity/cpuset 与有效 cgroup CPU quota 的较小值；同时检查父 cgroup 限制，不能直接使用宿主机逻辑核数。cgroup v2 看 cpu.max，v1 看 cpu.cfs_quota_us/cpu.cfs_period_us。
- 内存按 cgroup 限额减当前占用、宿主可用内存和同机活动构建综合评估，为链接和运行中任务留余量。结合该组件最近成功构建的峰值/并发选择可承受值；没有历史数据时先保守限制并监测，不把过去某台机器的 64 成功套用到小配额环境。
- 起始值不超过目标值、CPU 上限和内存可承受值，资源不足时可从 32、16 或更低开始，并记录限制原因。并行构建多个组件/系列时共享总预算，不能每个子任务各占完整额度；没有必要时顺序构建。
- LLVM/IR 链接默认 1，使用该版本支持的 LLVM_PARALLEL_LINK_JOBS=1/CMake job pool，预留单次链接所需内存。其他构建系统若不支持独立链接池，说明实际限制方式，不虚报已控制链接数。

## 让设置真正生效

将本轮选定值记为 BUILD_JOBS。它是编排变量，不假定上游会自动读取；在启动阶段显式传递：

```bash
export MAX_JOBS="${BUILD_JOBS}"
export CMAKE_BUILD_PARALLEL_LEVEL="${BUILD_JOBS}"
```

检查所选版本支持的参数，将 build-tools/build.sh -j、cmake --build --parallel 和直接调用的 ninja -j 设为同值。LLVM 链接限制须进入实际配置使用的 CMake 缓存；只设置一个不被读取的环境变量不算生效。

追到实际子进程或构建日志，确认 TorchNPU、TA、IR 每阶段的 -j，以及 LLVM_PARALLEL_LINK_JOBS/job pool。旧 runner 可能在子层使用 min(16, jobs)，或显式 -j 覆盖环境变量；优先使用官方配置开关，其次仅调整任务专用编排副本，不为提高并发改外部产品源码。记录请求值、实际值及证据位置。

## 有界降档

默认尝试序列为 64 → 32 → 16；先按本轮资源上限裁剪并去重。例如上限为 24 时只尝试 24 → 16，上限为 8 时只尝试 8。用户指定更高值时以该值起步，再使用低于它的 32、16 两档；资源预检仍适用。每阶段最多初次加两次降档重试，不重新遍历已失败档位。

1. 记录原命令、退出码及首条实质错误；比较本任务运行前后的 cgroup memory.events/oom_kill 或可读的 OOM 日志，结合进程树和峰值内存判断原因。
2. OOM、内存分配失败或与本任务对应的资源耗尽证据支持降档。单独的 exit 137、Killed 或超时不足以证明 OOM；先检查取消、外部终止及子进程状态，避免重复启动仍在运行的构建。
3. 确认本轮原构建及其子进程结束后，只对失败组件从下一低档续建；保留源码 SHA、编译选项、CANN、生成文件和成功产物。同步更新所有 -j 和环境变量，为每次尝试保留独立日志。
4. 同一阶段达到最小档仍失败、没有更低可用档位，或出现确定性首错时停止降档并报告具体阻塞。头文件/符号缺失、入口变化、版本或依赖不匹配、磁盘满、网络和权限错误按其原因处理，不消耗并发重试；资源原因未证实时也不盲目重试。

只有并发变化时无需清理构建缓存、重新 checkout 或重建已成功组件。某阶段已成功但打包/安装失败，应校正后续编排并复用 wheel。修正状态文件前核对产物，不能被历史失败标记永久阻挡，也不能把它直接改成成功掩盖实际失败。
