# 对接项目的日构建约定

在复用项目环境或 runner 时读取本文件。主机、路径、版本系列、CANN 和构建并发均来自当前项目及本轮请求；本技能不预设个人环境。

## 目标系列与环境入口

从适用的 AGENTS.md、项目环境说明和现有构建配置确定：

- 请求的 PyTorch/TorchNPU 系列及其源码 ref、依赖约束；指定单套时只处理该套，“全套”只沿用项目已明确维护的系列。
- TA 与社区 Triton 的配套，以及 NPU IR 分支、精确 SHA 和 LLVM gitlink；不因历史构建成功就复用旧组合。
- 当前 CANN、底层 Bisheng、Python ABI 和目标架构；不同 Weekly、beta 或补丁构建不视为等价，不随日构建自动升级基础栈。
- 主机连接方式、个人持久化目录、候选环境与正式激活入口，以及有效的个人 TorchNPU 补丁。

例如项目明确维护 2.7、2.10、2.13 时可分别搭建；这组系列不是其他项目的默认值。上游分支不再兼容指定系列时保留候选证据和旧环境，不能静默更换用户要求的系列。

按当前项目根目录解析其环境说明、资源规则与维护脚本。历史报告只用于还原相关构建方法，不将其中路径、SHA、设备测试 PASS 或调度状态视为当前事实。没有项目资料时，按 [构建参考](build.md) 与 [环境检查](validation.md) 定位实际入口；只补问影响正确性的缺项。

## 复用 runner

复用前读取入口及其直接依赖，确认工作目录、Python/CANN、系列选择、状态格式和阶段副作用；不只复制一个入口文件就假定可运行。

特别检查 verify、audit 等阶段是否同时合包、安装、迁移补丁、执行设备测试或切换正式入口。阶段名不能证明它适合作为本技能的环境检查命令。若旧验收包含设备测试，在任务副本中保留安装、导入及版本/入口检查，跳过设备测试和等待空闲卡的分支；只有任务包含正式更新时才保留切换动作。单套任务只复用对应构建能力，避免改动正式 runner 和无关系列。

并发取当前 CPU/内存配额与项目配置允许的值，区分编译和链接并发。资源不足可降低并发后有界重试；确定性的源码或依赖错误不靠反复降并发解决。

读取现有锁与进程状态后再续建。任务中断或历史自动任务被暂停都不授权恢复调度；只有明确的调度管理请求才查询或更新自动任务。
