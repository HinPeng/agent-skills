# 共享包查找、复用与归档

默认读取根目录为 /data/share，写入范围为 /data/share/<工号>/。先从用户说明、项目配置或已确认的 SSH 账号映射确定工号；不能使用 Windows 本机用户名代替，也不默认把 /data/share 改成历史出现过的 /data/shared。目录未挂载、无权限或工号未知时说明具体缺口；可继续个人目录内的构建，不将查找失败说成“没有匹配包”。

## 编译前先查

固定各组件完整 Git SHA 和目标配套后，先查 /data/share 中可读的包目录与构建记录，优先自己的目录，再查其他可读目录。按组件、版本、SHA 线索缩小搜索范围，再读取候选的邻接说明和 wheel 元数据；不要扫描全盘或修改他人权限。没有统一目录结构的旧包也可通过现有构建日志核实，不能只识别本技能新建的记录格式。

共享包满足以下条件即可直接使用，跳过对应组件的源码编译：

| 核对项 | 复用条件 |
|---|---|
| 源码身份 | 对应完整 Git SHA 一致；有未提交修改/补丁时明确其内容或变体标识，与目标要求一致。分支名、日期及文件名里的短 SHA 只作为查找线索 |
| Python 与平台 | wheel 的 Python ABI、平台、架构与目标解释器兼容，torch 系列及扩展编译 ABI 配套 |
| 编译依赖与选项 | CANN/Bisheng、相关子模块及影响二进制的构建选项一致，或有明确的官方兼容依据；仅并发数不同不要求重编 |
| TA/IR 合包 | 同时核对 TA SHA、包内 IR SHA、LLVM gitlink 与 payload 来源；不能仅凭 TA SHA 相同复用含另一版 IR 的合包 |
| 文件与状态 | 文件完整、来源记录足以判定身份和配套；不使用半成品、已知损坏或已知不兼容包 |

没有完整身份/配套信息时，先核对可用日志或包内构建标识；仍无法确认则说明该候选未采用的原因并构建缺项，不能推测完整 SHA。未做设备测试不妨碍环境包复用；只有编包成功而尚未安装验证的完整包，也可进入本轮候选检查，但不能提前标为环境就绪。

命中后记录来源路径及为何匹配，使用 [uv](uv.md) 安装到本轮候选，并执行 [安装与入口检查](validation.md)。复用文件不赋予修改来源目录的权限；默认读取或复制到个人目录，保留原包。部分组件命中时只编缺失项，不把局部命中视作整套环境完成。

## 编包后归档

默认目录示例：/data/share/<工号>/npu-daily/<本轮标识>/。本轮标识使用不会覆盖既有内容的日期/系列/提交组合或任务标识；目录名便于定位，完整身份以邻接记录为准。

1. 复制完成打包且通过归档/ZIP 完整性检查的 wheel，保留本地原产物。只归档本轮包与简短来源记录，不复制源码树、整个 venv 或无关实验数据。
2. 随包写一份简短 build-info.json 或沿用项目现有等价记录：列出文件名、组件完整 SHA、补丁/变体、IR/LLVM 来源、Python/torch/ABI/架构、CANN/Bisheng、影响产物的构建选项，以及构建与环境检查状态。只记录必要字段，不导出完整环境变量。
3. 针对实际复制的包核对源/目标大小与 SHA256。Git SHA 标识源码，文件 SHA256 核对传输完整性，两者不能互相替代；无需给源码、日志或整个环境生成哈希清单。
4. 上传或复制未完成时保留临时文件/暂存目录；全部核对后再发布为可复用目录或写完成标记。不能覆盖已有同名但内容不同的包；保持独立变体目录。记录中的“打包完成”“导入/入口检查通过”分别更新，不用设备 PASS 代替环境状态。
5. 交付共享目录与关键包的完整路径、归档核对结果及尚未验证项。只在自己的归档目录更新本轮状态；共享目录不可写时保留个人目录产物并报告归档未完成，不删除或重编成功包。
