# 环境检查、启用与恢复

## 核实实际环境

使用候选激活入口启动新 shell/进程，记录实际 sys.executable、torch/torch_npu 以及范围内 triton 的版本及 __file__、TA distribution、CANN 与底层 Bisheng。将请求的系列、已解析的构建标识与实际安装结果对照，不能用“可以 import”代替版本匹配。必要时检查已加载动态库。使用项目已有只做导入与版本检查的环境探针；没有时做简短直接检查，不运行设备算子或生成环境审计框架。

激活脚本只清理本轮子进程中已确认的旧 CANN/PYTHONPATH 或编译器覆盖项，保留所选 CANN 需要的 acl 路径；不修改系统环境和其他任务的 shell。先检查激活脚本是否支持 nounset，旧脚本不能无条件套 set -u。

用 uv pip check --python /absolute/path/to/venv/bin/python 检查依赖，对非零结果逐条辨别核心依赖冲突与继承的 CANN 工具依赖告警。记录实际退出码和适用边界；不要为求退出 0 删除必要 CANN 路径或补装整套无关软件。包管理工具故障的处理见 [uv 参考](uv.md)。

## 核实所选编译器入口

任务包含 TA/IR 时，读取目标 TA 版本的选择逻辑。若提供 _get_npucompiler_path()，取得其路径部分；不要打印可能带完整环境变量的返回对象。包内 bishengir 路径可能优先于 shell PATH，which 的结果不足以证明入口选择正确。只请求 torch/TorchNPU 包时将未涉及组件标为不适用，不因此自动扩大安装范围。

核对选中路径、--version、内部 HIVMC 和 CANN Bisheng 的来源及配套。此处只检查入口配置与版本，不启动 kernel 编译、子进程编译追踪或设备测试；不修改外部选择器来强制绕过版本不兼容。

## 结果状态

分别报告下载、构建、安装、导入、版本/入口检查及正式启用的结果；官方包标为“下载/安装”，不计作本地编译成功。仅下载时报告 URL、构建标识、文件路径和完整性检查，不启动安装、激活或导入验收。日构建完成不以设备测试为前提，也不等待空闲 NPU。记录真实命令退出码；Bash tee 管道立即保存原命令的 PIPESTATUS[0]。

一个系列失败不阻塞其他独立系列；构建、安装或核心环境检查失败的系列不切正式入口。环境搭建结果不代表算子功能、精度或性能通过。

共享包命中后仍需在本轮候选中执行上述检查，旧环境 PASS 不替代当前结果。按 [共享包参考](shared-packages.md) 更新本轮归档状态并交付路径，不改写他人的来源记录。CANN 有变更时额外核对新激活路径、底层 Bisheng 和编译缓存来源，按 [CANN 参考](cann.md) 保留恢复入口。

## 正式启用与恢复

仅构建独立环境时交付候选激活入口，不改正式 current。请求已包含更新正式环境时，在安装、导入及版本/编译器入口检查通过后完成切换，不重复请求已给出的授权。

切换前重新读取入口，确认它仍指向本轮预检时记录的版本；其他任务已更改则保留候选并解决并发冲突，不覆盖新入口。锁应覆盖完整入口切换。单个链接可在同目录创建临时链接再原子替换；多入口切换不是天然整体原子，需要记录已更新项并在失败时恢复。

用新 shell 检查切换后 Python、实际包、CANN 及编译器入口。失败则恢复本轮自己改动的入口，并检查恢复结果；保留旧环境、wheel 与候选日志。恢复命令应指向准确旧环境/激活入口，不通过删除新环境或重装基础栈实现。

交付简短版本表及候选/正式激活命令。仅在发生切换时列旧入口和可执行恢复命令；将版本、源码提交、构建变体、所选编译器与环境检查结果写入该轮现有记录，项目需要时更新报告索引。
