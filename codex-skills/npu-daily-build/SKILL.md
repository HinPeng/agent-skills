# NPU 日构建环境搭建

将请求的版本组合搭建为可激活、可验证、可恢复的个人隔离环境。完成范围内的获取、构建、安装及环境检查，不停在构建方案或 wheel 生成阶段。仅下载请求交付包、来源及安装入口，不安装或宣称环境就绪。日构建不运行设备算子测试，环境完成条件为安装、导入、版本配套和编译器入口检查。用户指令优先。

## 确定本轮目标

从请求和项目约定确定目标系列、日期/ref/提交、组件范围、主机及是否更新正式入口；只补问影响正确性的缺项。仅要求一套环境时不扩展为三套。指定历史日构建时先查已有产物和来源记录，不能改用今天最新；历史产物缺失且无法还原精确组合时说明缺口，不按日期猜 SHA。

明确获取方式：要求源码最新/ref/SHA 时固定源码身份，编译前先查共享目录中同提交且配套一致的已编包，命中则复用，未命中才构建；要求官方日包、日期包或提供下载脚本时核实官方产物；未指定方式则沿用项目现行方法。包不包含请求的 TA/IR 时只补齐缺项，不能将安装 torch/torch_npu 称为完整三组件构建。

“最新”在本轮开始时解析为具体提交或已发布构建标识，后续步骤及续建固定这些输入。仅搭建独立候选环境时保留原正式入口；明确要求更新正式环境时，环境检查通过后完成切换，无需重复确认已授权步骤。创建技能或询问构建方法本身不授权执行构建。

默认用 uv 管理环境与依赖；源码编译目标并发 **64**，按 CPU/内存实际余量限制，资源类失败有界降为 **32、16** 续建，链接默认 **1**。用户指定值和项目资源上限优先；具体执行与停止条件见下方参考。

共享包默认从 **/data/share** 的可读目录查找，编包完成后归档到 **/data/share/<工号>/**，记录源码身份、配套和验证状态。工号与目录映射按当前项目核实；复用及归档细则见下方参考。

## 工作边界

- 下载官方源码、正常构建、wheel 打包和候选环境安装属于搭建流程；不为修复产品缺陷修改 TA、NPU IR、LLVM 等外部源码或编译器二进制。必要的同版合包在独立打包目录完成。
- 使用个人持久化目录和隔离 Python，保留基础栈、旧环境及当前有效的个人补丁。通常沿用配套 CANN；出现版本问题时从官网选择适配的最新或历史包，远程下载失败可本机下载后上传，在个人候选中并行安装和验证。保留公共 CANN 与旧入口，不连带升级驱动、固件、系统 Python 或容器。
- 依据实际 CPU/内存配额安排构建，只管理本任务进程和产物。
- 该技能执行单轮构建或续建，不自动创建、恢复或改变定时任务；另有明确调度请求时再使用相应自动化工具。
- 复用项目现有构建脚本前确认其目标范围和副作用，尤其验收命令是否同时改写正式入口。旧路径、旧 SHA 和历史 PASS 都不是当前验收。

## 结果与完成条件

每个请求的系列分别报告：获取方式、选定源码/包版本、候选环境、当前启用环境、所选编译器入口、环境检查状态和日志；说明共享包命中/未命中及归档完整路径，源码构建补充实际编译/链接并发及降档原因。CANN 变更时说明选择依据、官网来源和候选路径。给出完整激活命令；发生切换时同时给恢复入口。仅下载、复用、构建/安装完成、导入通过及正式启用分别记录。

构建失败保留首条实质错误、命令、退出码和可续建产物；环境检查未通过时不切换正式入口。修正范围内的构建编排错误后继续受影响阶段，不无依据重跑全量。确定性错误或缺失外部条件无法解决时说明具体缺口。环境搭建完成不代表算子运行或精度验收。
